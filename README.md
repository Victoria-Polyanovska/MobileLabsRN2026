Для запуску програми необхідно спочатку встановити всі залежності командою npm install а потім активувати сервер через npx expo start після чого можна відкрити проєкт у браузері натиснувши клавішу w або відсканувати код у додатку Expo Go.

Реалізований функціонал включає повноцінну систему авторизації через глобальний контекст який захищає приватні екрани від неавторизованих користувачів. Головна сторінка відображає інтерактивний список товарів із зображеннями та цінами а при натисканні на будь-яку позицію спрацьовує динамічна навігація для переходу на екран із детальним описом конкретного виробу. 

3. Контрольні запитання

1. Яким чином за допомогою Expo Router реалізується
перенаправлення неавторизованого користувача?
У Expo Router це реалізується через файл макета (_layout.tsx) у захищеній групі маршрутів. Ми використовуємо стан авторизації з глобального контексту і якщо користувач не ввійшов у систему, повертаємо компонент <Redirect />. Це автоматично перериває відображення захищеного екрана та перекидає користувача на сторінку входу ще до того, як він побачить контент.
2. У чому полягає різниця між використанням компонента <Link>
та метода router.push()?
<Link>  це звичайна кнопка або посилання на сайті. Просто натискається і переходить. Це простіше і краще для самого додатка.
router.push() перехід відбувається «командою» в коді. Наприклад, натиснувши Увійти, програма перевірила введений пароль, зрозуміла, що він вірний, і сама дала команду входу.
3. Як працюють динамічні маршрути в Expo Router і як отримати
передані параметри?
Це сторінки-шаблони. Замість того, щоб робити окрему сторінку для кожного, ми робимо одну сторінку [id].tsx. Коли натискається на товар, роутер бере його номер (ID) і вставляє в назву.
4. Чому стан авторизації доцільно зберігати у глобальному
контексті (React Context), а не в локальному стані компонента?
Збереження стану авторизації в React Context забезпечує єдине джерело для всього застосунку. Оскільки статус авторизації впливає на логіку навігації, доступність екранів та відображення елементів інтерфейсу
5. Для чого використовуються групи маршрутів (folderName) і
як вони впливають на URL-адресу?
Групи маршрутів, назви яких беруться в круглі дужки, використовуються для логічного структурування файлів проєкту та застосування окремих макетів (_layout) до певних розділів застосунку без зміни структури посилань. Основна особливість полягає в тому, що назва групи повністю ігнорується при побудові URL-адреси.
